# RAG（Retrieval-Augmented Generation）とは

RAG は Retrieval-Augmented Generation の略で、日本語では「検索拡張生成」と呼ばれる。
大規模言語モデル（LLM）が回答を生成する前に、外部の知識ベースから関連する文書を検索し、その内容をプロンプトに含めてから回答させる手法である。

## なぜ RAG を使うのか

LLM は学習時点の知識しか持たず、社内文書や最新情報のような学習に含まれない情報には答えられない。
また、知らないことをもっともらしく作り話してしまう「ハルシネーション」が起きやすい。
RAG では回答の根拠となる文書を都度与えるため、最新情報や独自データに基づいた回答ができ、ハルシネーションを抑えられる。

## RAG の基本的な処理の流れ

RAG は大きく2つのフェーズに分かれる。

1. インデックス作成（事前準備）: 文書を読み込み、適切な大きさのチャンクに分割し、埋め込みモデルでベクトル化して保存する。
2. クエリ時: ユーザーの質問もベクトル化し、保存済みチャンクとの類似度を計算して関連の高いものを取得し、それをプロンプトに差し込んで LLM に回答させる。

## 主要な構成要素

- チャンク分割: 長い文書を検索しやすい単位に区切る処理。
- 埋め込み（エンベディング）: テキストを意味を表す数値ベクトルに変換する処理。チャットモデルとは別の埋め込みモデルを使う。
- ベクトル検索: 質問ベクトルに近いチャンクをコサイン類似度などで探す処理。
- プロンプト拡張: 検索で得た文書を「参考情報」として LLM への指示に加える処理。
